# 🛡️ Cyber Attack Prediction & Early Warning System

> A machine-learning pipeline and interactive dashboard that analyses network-traffic
> features to **predict cyber attacks in real time** and emit graded threat warnings
> before damage occurs.

---

## 📁 Project Structure

```
cyber-attack-predictor/
│
├── data/
│   ├── raw/            # Original, unmodified datasets (CSV, PCAP exports, etc.)
│   └── processed/      # Cleaned and feature-engineered files ready for training
│
├── notebooks/          # Jupyter notebooks for EDA, prototyping, and visualisation
│
├── src/                # Core Python library — import these in notebooks and the app
│   ├── __init__.py
│   ├── preprocessing.py   # Step 1 — data loading, cleaning, and encoding
│   ├── features.py        # Step 2 — feature engineering (entropy, rates, flags …)
│   ├── train.py           # Step 3 — model training, cross-validation, serialisation
│   ├── risk_engine.py     # Step 4 — probability → threat-level mapping (Low/Med/High/Critical)
│   ├── explain.py         # Step 5 — SHAP explanations for analyst transparency
│   └── predict.py         # Step 6 — load model + predict on a single feature dict
│
├── app/                # Streamlit multi-page web application
│   ├── __init__.py
│   ├── Home.py            # Landing page — live dashboard with threat metrics
│   ├── auth.py            # Login / logout / session management (bcrypt + session_state)
│   ├── db.py              # SQLAlchemy DB connection, schema helpers, prediction logs
│   └── pages/             # Additional Streamlit pages (auto-discovered by Streamlit)
│                          #   e.g. 1_Predict.py, 2_History.py, 3_Explain.py, 4_Admin.py
│
├── models/             # Serialised model artefacts (.pkl, .json) — never commit large files
│
├── tests/              # Pytest unit & integration tests for every src/ module
│
├── Dockerfile          # Containerises the app; run with `docker compose up`
├── requirements.txt    # Pinned Python dependencies (generated by `pip freeze`)
└── README.md           # ← you are here
```

## 🔄 Pipeline Overview

```
Raw Data  →  preprocessing.py  →  features.py  →  train.py
                                                      ↓
User Input  →  predict.py  ←  models/  ←  serialised model
                   ↓
             risk_engine.py  →  Threat Level (Low / Medium / High / Critical)
                   ↓
              explain.py     →  SHAP waterfall / bar chart
                   ↓
              app/Home.py    →  Streamlit Dashboard
```

## 🐳 Docker Deployment Instructions

The application is fully containerised with Docker and Docker Compose for portable, reproducible deployments.

### Prerequisites
- [Docker Engine](https://docs.docker.com/engine/install/) or [Docker Desktop](https://www.docker.com/products/docker-desktop/) (v20.10+)
- [Docker Compose](https://docs.docker.com/compose/) (v2.0+)

### Option A: Using Docker Compose (Recommended)

Docker Compose automatically handles container builds, port mappings (`8501:8501`), and mounts persistent volumes for SQLite databases and trained models.

1. **Build and start the container in detached mode**:
   ```bash
   docker compose up --build -d
   ```

2. **Verify container status and logs**:
   ```bash
   docker compose ps
   docker compose logs -f
   ```

3. **Access the dashboard**:
   Navigate to **`http://localhost:8501`** in your browser.

4. **Seed or manage administrative users inside the container**:
   ```bash
   # Seed admin with custom password
   docker compose exec cyber-attack-predictor python scripts/seed_admin.py --username admin --password "YourCustomPassword!" --role admin
   ```

5. **Stop the container**:
   ```bash
   docker compose down
   ```

### Option B: Using the Docker CLI Directly

1. **Build the Docker image**:
   ```bash
   docker build -t cyber-attack-predictor .
   ```

2. **Run the container with volume persistence**:
   ```bash
   # On Windows (PowerShell):
   docker run -d -p 8501:8501 `
     -v ${PWD}/data:/app/data `
     -v ${PWD}/models:/app/models `
     --name cyber_predictor_app `
     cyber-attack-predictor

   # On Linux / macOS:
   docker run -d -p 8501:8501 \
     -v $(pwd)/data:/app/data \
     -v $(pwd)/models:/app/models \
     --name cyber_predictor_app \
     cyber-attack-predictor
   ```

3. **Check container logs**:
   ```bash
   docker logs -f cyber_predictor_app
   ```

4. **Stop and remove container**:
   ```bash
   docker stop cyber_predictor_app && docker rm cyber_predictor_app
   ```
